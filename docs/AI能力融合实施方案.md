# 《当骰一棒》AI 能力融合实施方案

版本：V1（2026-09-20）
定位：在现有本地原型（规则 AI 已跑通）之上，落地 Agent 决策、RAG 检索、Harness 架构三件套。本文档为实施与答辩依据。

## 一、可行性结论

| 能力 | 结论 | 核心依据 | 主要风险 | 对策 |
|------|------|----------|----------|------|
| Agent（LLM 决策） | **可行** | 引擎已暴露"合法行动列表 + canUseTool 校验"，行动空间是有限枚举（4 方向滑行 / 用哪张牌 / 选哪个目标），输出可结构化、可验证，远比开放文本生成可控 | 延迟 1–3s、调用费用 | 每回合仅 1 次动作由 LLM 决策，其余动作交规则 AI；qwen-turbo 级模型成本可忽略 |
| RAG 检索 | **可行，成本极低** | 知识源现成（docs/*.md + tools/characters/terrains 定义文本），知识库仅数百 chunk，本地 JSON + 余弦相似度暴力检索即可，无需向量数据库 | 检索噪声 | 每个道具/角色/地形天然成块，切片质量高；top-3 + 引用来源 |
| Harness 架构 | **可行，地基过半** | 规则 AI（ai.ts）= 现成降级兜底；引擎 = 现成工具面；node:test 自动完赛测试 = 现成评估地基；对局日志 = 现成解说数据源 | 纯架构重组，无新技术风险 | — |

总判断：**三项均可行，且任何一项失败都不会影响游戏可玩性**（降级路径保证对局始终成立）。这是"渐进增强"式融合，不是推倒重来。

## 二、实施方案（三阶段）

### 阶段一：Harness 骨架 + Agent 决策（约 1 天）

新增 `src/agent/` 目录：

```
src/agent/
├── registry.ts    # 工具注册表：把引擎能力包装成 3 个 function
│                    playMoveCard(dir) / playToolCard(uid, params) / endTurn()
│                    由引擎状态实时生成每步"合法行动清单"喂给模型
├── context.ts     # 感知层：buildSnapshot(state, playerId)
│                    → 精简 JSON：自身位置、手牌、对手位置、BFS 距离、周边地形
├── rag.ts         # RAG 检索：topK(query, k=3)，供决策与教练共用（见阶段二）
├── loop.ts        # 决策循环：感知 → RAG 补规则 → LLM(function calling/JSON mode)
│                    → 返回 { action, params, reason }
├── guardrails.ts  # 护栏：2s 超时 / JSON schema 校验 / canUseTool 复验
│                    / 每回合 LLM 配额(1 次) / 失败即降级 aiStep()
└── trace.ts       # 追踪：每步留痕 prompt / 检索片段 / 模型输出 / 最终动作
```

GameScreen 接线点：AI 回合首动作走 `loop → guardrails → 引擎`，后续动作沿用 `aiStep` 的 650ms 节奏。模型：DashScope qwen 系列，API Key 走环境变量。

**验收**：人机对局中 AI 至少完成一次"LLM 决策"动作；人为制造超时/非法输出，对局不中断、不出现非法棋。

### 阶段二：RAG 知识库 + 双消费方（约半天）

```
scripts/buildKb.ts   # 一次性入库：docs/*.md 按 300 字滑窗切块
                     # + TOOLS/CHARACTERS/TERRAINS 每条定义一块
                     # → 调 DashScope text-embedding-v3 → 生成 kb/vectors.json
```

消费方 A（决策 grounding）：`loop.ts` 根据 AI 当前手牌与所在地形检索对应规则片段注入 prompt，防规则幻觉。
消费方 B（新手教练）：GameScreen 加"？"按钮 + 问答面板，玩家提问 → top-3 检索 → LLM 生成回答并**附引用来源**。

**验收**：20 条固定问句集，回答正确率 ≥ 90%，且每条带引用。

### 阶段三：解说 + 评估台（约半天）

- AI 战报解说：回合结束把 trace 中的动作流水交 LLM 生成 1–2 句播报，写入对局日志区。
- `eval/evalRunner.ts`：`npm run eval` 批量跑 N 局 × 3 图，输出指标对比：胜率 / 平均完赛步数 / 非法动作次数 / 平均决策延迟 / token 费用。改 prompt、换模型前后各跑一次即为回归测试。

**验收**：一次 `npm run eval` 产出对比报告；解说在真实对局中出现。

## 三、与众不同的地方（创新点论证）

市面桌游 AI（含电子化桌游）的三个天花板 vs 本项目对应突破：

| 市面桌游 AI | 本项目 |
|-------------|--------|
| 策略硬编码，AI 不"理解"规则，只反射 | **知识驱动的对手**：RAG 把规则文本变成 AI 的工作记忆，靠推理而非查表行动 |
| 新增道具必须改 AI 代码、重新测试 | **规则即数据**：新道具只需一条规则文本入库，AI 下局即会检索、评估、使用——决策代码零改动 |
| 对手沉默执行，无社交 | **可对话的桌游**：AI 能解释动机（reason 字段）、能教学、能播报，把桌游核心的社交体验带回单机/线上对局 |
| AI 表现靠肉眼判断 | **可评估的智能**：Eval 台让 AI 成为可回归测试的软件组件 |

杀手级演示（答辩用）：现场向知识库添加一条新道具规则（如"橡皮擦：擦掉一格墙"），不改任何代码，下一局 AI 即会使用该道具。

电梯陈述：市面桌游 AI 的策略是开发者写死的；我们把规则做成可检索的知识库，对手靠推理而不是查表来玩——加新内容不用改代码，AI 会自己学会。三个 AI 岗位（对手/解说/教练）跑在同一套 harness 上，加第四个岗位只需注册新工具，不改骨架。

## 四、诚实边界（答辩备询）

- LLM 单步决策不保证全局最优；但引擎校验保证**永远合法**，规则 AI 保证**永不宕机**——智能可以降级，体验不能降级。
- LLM 决策有 1–3s 延迟，通过"回合首动作用 LLM、其余规则接管"的混合策略控制在可感知范围内。
- 本地原型阶段向量检索用 JSON 暴力余弦即可（数百 chunk 毫秒级）；文档注明生产规模应替换为向量数据库。
- 模型 API 不可用时游戏完全可玩（纯规则模式），符合需求说明 V1"可降级智能体"的原设计。

## 五、实施顺序总览

1. 阶段一 harness 骨架 + LLM 决策 + 护栏降级（1 天）
2. 阶段二 RAG 入库 + 决策 grounding + 教练问答（0.5 天）
3. 阶段三 解说 + 评估台（0.5 天）

三阶段独立可交付，任意中断均不影响已有功能。
