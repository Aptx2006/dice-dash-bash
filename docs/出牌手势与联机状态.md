# 出牌手势与联机状态

日期：2026-10-28。软件开发记录，实验6报告保持未填写。

## 玩家操作

卡牌现在支持点击、向上拖出和Enter/空格三种方式。需要方向或落点的牌仍先进入目标选择，只有选择合法目标后才消耗手牌。一次手势最多触发一次操作，拖出结束牌不会把行动阶段和回合结束阶段一起跳过。

旧实现只记“是否曾拖过阈值”，拖回原处仍会使用。现在按松手时的位置判断，向上不足46像素、拖回、水平/向下拖动、Esc、指针取消和窗口失焦均不提交拖牌。移动超过8像素会被视为拖动意图，取消后附带的浏览器click不能再误出牌；小范围点击抖动仍允许使用。多指事件只由最初的主指针控制，右键和第二根手指不能接管当前手势。

实现位于`src/input/cardGesture.ts`与`src/components/ToolHand.vue`。前者处理手势状态，后者负责指针捕获、事件清理、视觉位移与实际激活；规则、持牌和联机版本验证继续由原入口处理。教学说明和game-v4知识同步说明点击/拖动操作。

## 房间状态

对局中的房间状态按钮可以打开实时成员表，显示房主、当前行动者、自己的角色以及在线、离线等待重连、机器人和AI代打。行动顺序也显示这些简短状态。暂时断线超过20秒后显示AI代打，原身份重连后恢复在线；主动离开后身份注销规则不变。

界面连接中断时解释正在自动重连；服务恢复等待或存储暂停时显示对应原因，并禁止出牌。成员表不会显示其他人的手牌或身份凭证。使用原生dialog，支持关闭按钮和Esc，弹出层不受棋盘裁切。

智能对手统计改用“分析尝试、云端执行、规则接管”，避免把请求占位误写成分析已完成，也不把服务端规则策略称作本机浏览器策略。重启中断分析的`SERVER_RESTART`在复盘中有明确名称。

## 服务诊断

`GET /api/health`在正常时返回200，增加`rooms`对象：`paused`、`persistenceEnabled`、`roomCount`、`recoveringCount`。存储写入失败导致房间暂停时返回503和`ok:false`，避免进程还活着就误报服务完全正常。该接口只返回状态和数量，不返回房间号、玩家、token或游戏快照。

## 验证

- 6项手势事件序列测试：普通点击、拖动后兼容click、拖回取消、水平/向下和微小抖动、多指/右键、Esc/失焦取消与辅助点击。回拖、多指和持按Esc通过事件序列验证，未宣称覆盖所有真实触摸设备。
- HTTP故障注入检查正常200与暂停503，确认不泄漏游戏或身份信息；故障使用独立合成存储，不破坏玩家数据库。
- 实际双页面房间186318：点击投骰4点与砌墙，两端同步；成员表显示两个真人和一个机器人。朋友页面离开后立即显示离线，宽限期后变为AI代打，返回后恢复在线。后续工作中断后房间已失效，重新读取两端及健康状态，再开新房间验证，没有沿用旧棋盘定位。
- 实际房间355555：点击投骰6点、点击移动后显示方向预览，选择右移至(6,9)后消耗牌；向上拖出结束只进入回合结束阶段，下一次独立点击才交给机器人。第3回合把投骰牌上拖约21像素，仍保持回合开始且未发牌；随后单击投骰正常得到6点与瞬移。点击瞬移并选择终点后正确结束，第3回合胜出；结算可返回大厅重赛。
- 最后追加多指保护时，直接判断click的isPrimary使普通浏览器点击失效，单元测试未覆盖这个组件边界。实际页面复查发现后，改按已开始手势的指针编号排除其他手指，补充对应事件序列；独立26牌页面再次单击移动，正确显示方向预览，控制台error为空。没有把这一度失败的检查写成从未出过问题。
- 165项自动测试全部通过，前后端类型检查与生产构建通过，仍有Three.js对局分块约569KB提示。截图保存在本机`tmp/game-development`，不上传；原本地练习存档未覆盖。
