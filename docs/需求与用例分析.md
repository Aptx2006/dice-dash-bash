# 《当骰一棒》需求与用例分析

版本：V1.0  
对应需求基线：`需求说明V1.md`  
项目：浏览器端类桌游多人回合制竞速游戏

## 1. 系统边界与参与者

系统边界是“当骰一棒”浏览器游戏及其房间、回合规则、智能体和结算模块。账号社交、付费、语音、UGC地图和手机原生客户端不属于本版本。

参与者如下：

| 参与者 | 目标与权限 |
| --- | --- |
| 玩家 | 创建或加入房间、选择角色、准备、投骰、移动、使用道具、结束回合、查看结算 |
| 房主 | 具备玩家全部能力，并选择地图、添加/移除智能体、开始或结束房间 |
| 智能体 | 读取公开局面和合法行动列表，返回行动建议及理由；超时或非法时由规则策略接管 |
| 模型服务 | 可选外部AI服务，仅接收结构化局面并返回结构化行动建议 |
| 浏览器/网络 | 承载界面、发送操作请求和接收状态同步 |

房主是玩家的特化角色；智能体由房主加入房间后参与回合。规则引擎和状态同步属于系统内部组件，不作为外部参与者。

## 3. 核心用例描述

### UC-01 创建房间（P0）

- **前置条件：** 玩家处于首页，昵称符合长度和内容校验。
- **主流程：** 输入昵称 → 点击创建 → 系统生成唯一房间码 → 创建者成为房主并进入大厅。
- **异常流程：** 昵称为空/非法时拒绝创建并提示；房间服务不可用时保留输入并允许重试。
- **后置条件：** 房间状态为准备中，房主可配置地图和参与者。
- **验收：** 合法昵称创建成功并显示房间码；非法昵称不创建房间。

### UC-02 加入和准备（P0）

- **前置条件：** 房间码有效且房间未开始、人数未满。
- **主流程：** 玩家提交房间码 → 进入大厅 → 选择角色 → 点击准备 → 成员列表同步更新。
- **异常流程：** 房间不存在、已结束或已满时停留加入页并提示原因。
- **后置条件：** 玩家状态为已准备或未准备，房主可查看所有成员。
- **验收：** 双浏览器使用有效房间码可加入；无效房间码不会进入棋盘。

### UC-03 添加智能体（P0）

- **前置条件：** 当前用户为房主，房间仍在准备阶段且未达到人数上限。
- **主流程：** 房主点击添加智能体 → 选择策略/角色 → 系统加入已准备智能体。
- **异常流程：** 房间已满或配置冲突时拒绝添加并提示。
- **后置条件：** 成员列表出现智能体，满足开局人数要求。
- **验收：** 人数不足时可添加1—3名智能体并开始人机对局。

### UC-04 投骰与移动（P0）

- **前置条件：** 对局已开始且轮到当前玩家。
- **主流程：** 投掷移动骰 → 显示点数 → 计算并高亮合法落点 → 玩家选择落点 → 服务端校验 → 更新坐标并广播。
- **异常流程：** 落点越界、穿越障碍或不是当前回合时拒绝，棋盘状态保持不变。
- **后置条件：** 移动完成，进入道具阶段或结束回合。
- **验收：** 合法移动能同步到所有客户端；非法移动不改变状态。

### UC-05 使用道具（P0）

- **前置条件：** 玩家持有道具且处于允许使用的回合阶段。
- **主流程：** 选择道具 → 选择合法目标/方向 → 展示影响 → 玩家确认 → 服务端扣除道具并执行效果。
- **异常流程：** 目标无效、信息不足或重复使用时提示原因且不扣除道具。
- **后置条件：** 道具效果生效并同步，或玩家取消选择。
- **验收：** 影响他人的道具必须二次确认；非法目标不会产生效果。

### UC-06 智能体行动（P0）

- **前置条件：** 轮到智能体，系统已生成公开局面和合法行动列表。
- **主流程：** 请求模型建议 → 解析行动和理由 → 规则引擎校验 → 执行合法行动并同步。
- **异常流程：** 模型超时、无法解析或返回非法行动时，记录原因并使用确定性规则策略。
- **后置条件：** 智能体在限定时间内完成回合，不阻塞后续玩家。
- **验收：** 正常响应不超过5秒；失败时两秒内完成降级行动。

### UC-07 断线重连（P1）

- **前置条件：** 玩家曾加入房间且服务端仍保存房间状态。
- **主流程：** 网络恢复 → 客户端携带房间和玩家标识重连 → 服务端返回最新确认状态。
- **异常流程：** 房间已结束或状态不可恢复时返回大厅并提示。
- **后置条件：** 客户端显示与服务端一致的棋盘和回合信息。

### UC-08 结算与复盘（P0）

- **前置条件：** 任一参与者到达终点，或满足结束条件。
- **主流程：** 服务端确认终点 → 锁定继续操作 → 按到达顺序和距离生成排名 → 展示回合数、关键行动和AI降级次数。
- **后置条件：** 对局状态为已结束，可返回房间或首页。
- **验收：** 到达终点后不能继续投骰；结算页显示排名和摘要。

## 4. 用例之间的关系与优先级

P0闭环为 UC-01 → UC-03/UC-02 → UC-05 → UC-06 → UC-04/UC-05 → UC-08。UC-07断线重连为P1，在核心闭环稳定后实现。UC-10行动校验和UC-11状态同步被多个回合用例复用，是可靠性和多人一致性的基础。

## 5. 非功能约束映射

| 约束 | 关联用例 | 验收指标 |
| --- | --- | --- |
| 性能 | UC-04、UC-06、UC-11 | 95%状态同步≤500ms；AI正常响应≤5s |
| 可靠性 | UC-04、UC-05、UC-06、UC-07 | 非法操作不改变状态；AI失败自动降级 |
| 安全 | UC-01、UC-02、UC-06 | 昵称/房间消息校验；模型密钥仅服务端可见 |
| 可用性 | 全部 | 当前阶段、可执行操作和错误原因始终可见 |
