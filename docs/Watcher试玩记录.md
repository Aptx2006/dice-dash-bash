# Watcher 实机试玩记录

记录日期：2026-09-14。本文随试玩更新，用于《当骰一棒》后续开发。仅将实际界面或操作结果确认为规则，推测单独列出。

## 1. 试玩环境与控制问题

- 参考站：http://watchergame.cn:5173/ ，应用内浏览器。
- 用户创建房间后，助手接手添加 AI、准备并开始对局。
- 页面控制存在明显延迟：DOM 读取约 21—33 秒，包含自动读取的标签选择可能需要 42 秒；默认 30 秒调用会超时。部分操作在超时前已经生效，因此必须读取状态后再决定是否重试。
- 恢复方法：使用浏览器的直接标签接口和 DOM 定位；操作与观察分开调用，单次超时上限设为 60 秒。并未修改站点源代码或浏览器安全设置。

## 2. 大厅：已实测

1. 房间标题为“竞速模式 图一”，有连接状态与在线人数，最多显示八个位置。
2. 房主默认角色“村民 / Villager”，说明“没有任何技能”。角色和棋子分别选择，玩家名可修改。
3. 房间号默认隐藏，可显示或复制。
4. 点击“添加AI玩家”后出现一名 Robots AI；AI 自动准备。
5. 点击“准备”后变为“取消准备”，提示所有在线玩家已准备，“开始游戏”可用。
6. 关闭每回合 75 秒限制后进入对局，方便慢速观察。

大厅机制开关的原文含义：

| 选项 | 界面说明 | 本次配置 |
| --- | --- | --- |
| 允许作弊 | 允许玩家在行动阶段通过调试入口获得工具 | 关闭 |
| 空降骰子猪 | 开局在随机位置降下携带随机奖励的骰子猪 | 开启 |
| 每回合75s时间限制 | 超时自动结束回合 | 已关闭 |

## 3. 对局界面：已观察

- 大面积立体方格棋盘；深色墙块、绿色骷髅地块、问号地块、蓝色箭头地块、木桩障碍与粉色骰子猪。各地块的具体效果尚待实际触发。
- 两名玩家的行动顺序位于棋盘右侧；人物与骰子猪可在同一位置附近出现。
- 底部是横向工具手牌区域，左侧显示当前玩家、阶段和棋子形象，右侧是可按住查看的角色卡。
- 开局阶段明确显示“回合开始”，中间有“投骰”手牌，说明为“投掷工具骰和移动骰，进入行动阶段”。

## 4. 操作试验

| 操作 | 实际反馈 | 结论 |
| --- | --- | --- |
| 添加 AI、准备、开始 | 成功进入立体棋盘 | 大厅到开局流程已验证 |
| 单击投骰按钮 | 随后仍显示“回合开始”，卡片仍在 | 不能认定单击完成投骰；下一步验证拖拽手牌 |
| 用户拖出投骰牌 | 进入行动阶段，出现移动、钩锁、结束三张牌 | 投骰采用拖牌操作，用户已明确说明 |
| 助手拖出移动牌 | 移动牌消失，工具和结束牌仍保留 | 移动后不会自动结束回合 |
| 助手拖出钩锁牌 | 钩锁牌消失，粉色玩家棋子出现在左侧相邻通道，另一棋子留在原处 | 工具可在移动后使用；本次出现实际位移 |
| 助手拖出结束牌 | 已操作，下一步读取 AI 回合后的状态 | 待验证回合交接 |

### 第一回合获得的牌面

- **移动**：朝指定方向前进 **3** 格。不是任选若干步内的目的地。
- **钩锁**：发射长度为 **4** 的钩锁，将自己拉向墙壁，或者将目标拉到身前。
- **结束**：结束当前阶段。
- 手牌消耗后，其余卡片自动重新居中排列。因此不能重复使用上一张截图中的卡片坐标。
- 移动后第一张截图未观察到明显位置改变，是否因为墙体阻挡尚待下一回合验证。不能将该次操作认定为成功前进三格。

## 5. 对当前实现的影响

- 当前《当骰一棒》的侧栏投骰按钮与 Watcher 底部手牌交互有明显差异；应在确认手牌操作后调整。
- 当前 8×8 地图、冲刺/换位/护盾和三类初始道具角色是已有雏形设计，不能当作 Watcher 的实测规则。
- 需要继续验证：投骰手势、移动方式、工具骰结果、道具目标、回合结束条件、骰子猪奖励、终点与结算。

## 6. 源码级调研（构建产物逆向，2026-09-14 补充）

直接抓取原型 Vite 构建产物（JS/CSS 分块）并用脚本提取字符串/标识符/颜色，还原出比试玩更完整的设计：

1. **移动模型是方向牌制**：移动卡写"朝指定方向前进 N 格"，是整段直线滑行，不是 BFS 任选落点；途中被墙/玩家阻挡即停。罗素（制动）可中途提前停止。
2. **回合三阶段**：`回合开始`（投骰/复制/备锁/飞跃/风暴巨剑卡）→ `行动阶段`（移动/工具/结束卡）→ `回合结束`（钱包/炸药/招魂卡）。系统卡每阶段重建，库存工具跨回合保留。
3. **角色全量 15 名**：村民（白板）、罗素（制动）、鹅哈哈（每回合篮球）、兰彭（复制）、领导（钱包）、布拉泽（炸药）、锁（备锁）、心（小幽灵：移魂/招魂）、暴风（风暴巨剑）、芙兰迪（飞跃）、常（钩锁成长 1→5）、法真（制衡）、莫汀（砌墙）、让（移动-2+瞬步）；另有 AI 用威猛机器人。
4. **道具 20+ 种**：冲刺/拳击/篮球/钩锁/砌墙/炸药/火箭/瞬移/瞬步/牵引（骰子池）+ 系统与角色专属（移魂/招魂/钱包/制衡/飞跃/复制/风暴巨剑/备锁）。
5. **地形 12+ 种**：地板、墙、高墙、土墙（耐久）、坑洞、毒气（骷髅格）、传送带、大炮、幸运方块、家园、起点、终点、拳击球（木桩）。
6. **三种模式**：竞速 / 对战 / 整蛊，本次复刻仅实现竞速。

## 7. Playwright 实机验证（网络恢复后，2026-09-14 补充）

改用 Playwright 控制本地 Chromium 重测原型，确认了几个关键结论：

| 事项 | 实测结论 |
| --- | --- |
| 投骰交互 | 向上拖出手牌即打出（拖拽阈值约 46px）；直接点击也生效 |
| 钩锁长度 | 默认 4（常初始 1，每用一张牌 +1，最多 5） |
| 视觉风格 | 浅色奶油系：纸色 `#f4edda`、Georgia 衬线大标题、主按钮黄 `#f2d25c`、薄荷绿 `#9fe3c0`、文字藏青 `#2c3550`；地板木色、墙深蓝 |
| AI 命名 | `Robots-935号` 样式（机器人名 + 三位随机编号） |
| 回合计时 | 每回合 75s，顶部细进度条 |

之前章节"需要继续验证"的清单至此全部有答案：投骰=拖牌/点击；移动=方向滑行；工具骰给随机道具；道具按类型选方向/落点/玩家；回合结束打结束卡；骰子猪经过即触发三选一奖励；首个到终点者获胜并显示"回合到达：第 N 回合"。

## 8. 《当骰一棒》复刻版本地自测（2026-09-14）

按以上情报完成的复刻版已通过本地验证：

1. **自动测试 16/16 通过**（`npm test`）：方向滑行、墙阻挡、罗素制动、坑洞回出生点、传送带顺行+1、土墙耐久消耗、幸运方块三选一、炸药跨回合引爆击退、击退入坑、终点获胜排名、系统卡生命周期、相机自适配，以及 **4 AI 在三张地图上全自动对局全部完赛**（4000 步上限内）。
2. **构建零错误**：`vue-tsc -b` 类型检查通过；对局页面按需加载后，首页脚本约 109 kB，包含 Three.js 的对局脚本约 521 kB。
3. **Playwright 实机流程 0 页面错误**：主页选图创建房间 → 大厅选罗素 → 添加 2 个威猛机器人 → 开局投骰 → 移动滑行 → 骰子猪奖励弹窗三选一 → 结束行动/回合 → 两个 AI 各自完整行动（投骰、瞬步、捡猪、选奖励）→ 第 4 回合正常轮回到真人再次投骰。75s 计时条、行动顺序、日志面板均正常。

### 本次复刻的简化决策

- 传送带：简化为"顺行方向 +1 步"。
- 终点：第一个到达者即结束对局（按项目方案），结算按"回合到达"排序。
- AI 命名沿用原型风格：`威猛机器人-XXX号`。
- 对战/整蛊模式暂不实现，主页按钮置灰。
