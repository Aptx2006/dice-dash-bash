# 多人房间与权威同步

更新日期：2026-10-28。本文记录软件实现与可复现验收，不是实验6报告。

## 使用流程

`npm run dev:all`同时启动界面与AI/房间服务。首页“创建联机房间”生成6位码，朋友在同一服务输入房间码加入。每位真人可选择自己的角色与棋子颜色，房主可选择地图、空投、计时和机器人模式，并添加机器人。设置改变后其他真人重新准备。至少两名选手、所有真人连接并准备，才能开始。

“本地练习”和基础教学保留原有离线引擎和自动存档。联机身份使用sessionStorage单独保存，不覆盖本地最近一局；复制邀请链接不包含身份凭证。若使用多个标签页模拟独立玩家，使用“加入房间”取得新身份；直接复制已登录标签页可能复制浏览器会话，不能视为独立玩家。

同标签页刷新读取服务端最新局面。断线超过20秒由AI接管，重连时恢复真人控制；主动离开注销原凭证，对局中的座位交给AI。房主离开会移交给剩余真人。结算由房主带全员回大厅，其他真人重新准备。默认真人计时75秒，投骰统一保留4秒演出时间，不能通过调慢动画延长服务端回合。

## 协议与可信边界

| 接口 | 输入/用途 | 认证 |
| --- | --- | --- |
| POST `/api/rooms` | 昵称、地图，返回房间与本方凭证 | 无 |
| POST `/api/rooms/:id/join` | 昵称，加入尚未开始的房间 | 无 |
| GET `/api/rooms/:id` | 当前玩家可见快照 | Bearer |
| GET `/api/rooms/:id/events` | SSE，初始快照、状态更新、15秒心跳 | Bearer头 |
| POST `/api/rooms/:id/commands` | requestId、expectedRevision、白名单command | Bearer |
| POST `/api/rooms/:id/suggest` | 战术目标，服务端构造真实局面 | Bearer |

服务端持有完整GameState、每房间独立的随机密钥与计数器。投骰、AI与实际道具使用同一引擎，客户端只提交操作意图。私有随机流使用HMAC生成，密钥与计数器不放入快照。非法操作在副本中被拒绝，未提交的局面不广播。

每位玩家仅收到自己的完整手牌；别人的手牌数组和未选择奖励内容清空。已打出的牌与骰子通过公开presentation事件演出。前端收到意外泄漏手牌的投影会拒绝渲染。模型输入使用已有的私有信息投影函数，模型只能提出行动编号，不能任意改写状态。

非当前真人、无权修改房间的成员、未持有的牌、错误阶段、非法目标、额外参数和过期版本均被拒绝。每名成员保留最近128个成功请求编号，同编号同操作只执行一次，同编号不同操作拒绝。客户端断线禁用操作，网络恢复后重新接收完整权威快照，不盲目重放旧操作。

revision标识规则和大厅变化，syncId标识连接/思考状态的广播次序。客户端丢弃迟到的旧快照。SSE使用认证头而非URL参数，每席位最多两条流，慢连接受发送缓存上限保护。35秒收不到任何字节会关闭流并重连，退避从300毫秒增加到3秒。

## Agent、RAG与Harness如何参与

| 课程能力 | 游戏中的行为 | 约束与可观察结果 |
| --- | --- | --- |
| RAG | 规则教练、战术与对手查阅规则 | 22条game-v2知识，来源编号和原文可展开；历史实验5结果仍使用旧快照 |
| 自主工具调用 | 战术助手查询局面、枚举行动、隔离推演、查规则 | 最多8步、45秒、2次纠错；记录工具过程，确认前不出牌 |
| 自主智能对手 | 服务端每个AI回合最多分析一次有意义的局面 | 5秒预算、结构化行动复验、失败规则接管，保留最近20条摘要 |
| Harness | 控制器管理时限、取消、降级、轮次/版本和执行 | 重连取消迟到AI请求；过期战术确认不能执行；计数分别记录请求、云端执行与接管 |
| 软件工程可靠性 | 房间权限、私有投影、幂等命令、重连与结算 | 自动化边界测试和双页面实际对局，不把单次模型样本当作胜率证明 |

## 运行范围与限制

默认仅本机。`npm run dev:all -- --lan`显式开启可信局域网：前端监听0.0.0.0，房间/AI后端仍监听127.0.0.1，通过Vite代理访问；启动器把实际私有IPv4地址的5173来源加入白名单。也可在受控部署中显式配置`GAME_ALLOWED_ORIGINS`，逗号分隔完整origin。未配置的非回环来源被拒绝。不修改防火墙或部署公网，不提供账号、TLS终止、数据库或生产运维设施。

最多32个内存房间，每房最多8席位；创建/加入每服务连接IP每分钟30次。开发代理下连接IP可能相同，这是演示限制。全服务共用模型并发2、10分钟30次预算，繁忙时AI按规则继续。

房间创建满2小时或无状态变化30分钟会清理，所有真人主动离开会关闭。服务进程重启会丢失房间，不提供服务重启后的恢复；浏览器本地练习存档仍独立保留。网络流发送全量快照，适合当前小规模课程原型，未做公网压力和真实跨设备延迟测试。

## 验收方式

`npm test`覆盖房间权限、准备重置、版本和重复请求、私有投影、服务端计时、掉线接管/重连、迟到模型取消、AI完赛及重赛；HTTP集成测试真正建立两个认证SSE流，同步创建、加入、投骰和非法命令拒绝。来源白名单包含允许/拒绝用例。
