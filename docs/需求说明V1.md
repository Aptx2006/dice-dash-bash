# 《当骰一棒》需求说明 V1

版本：V1.0  
状态：需求基线草案

## 1. 问题陈述

目标用户是在宿舍、社团或线上语音中寻找轻量多人游戏的大学生。在朋友临时想开一局游戏、设备和平台不统一或人数不足时，购买大型客户端、安装与组队会增加开始成本，而普通网页棋盘的电脑玩家策略较弱。项目拟提供浏览器房间、回合制竞速规则和可降级的智能体对手，让用户更快完成一局可玩的对局。

## 2. 用户画像

### 2.1 主要用户：大学生休闲玩家

- 目标：与朋友快速开始一局20—30分钟的轻量游戏。
- 能力：会使用浏览器和房间码，不要求掌握复杂桌游规则。
- 环境：Windows或macOS电脑，普通校园网或家庭网络，可能同时使用语音软件。
- 约束：时间有限、网络可能波动、参与人数不固定。
- 痛点：安装和组队成本高；人数不足；规则提示不清；等待其他玩家行动时间过长。

### 2.2 次要用户：房主

房主负责创建房间、选择地图、添加智能体和开始游戏，希望能看懂配置影响，并在玩家掉线时继续或结束房间。

## 3. 场景

### 正常场景

1. 玩家输入昵称创建房间，系统生成房间码并显示准备大厅。
2. 好友输入有效房间码加入，选择角色并准备，房主开始游戏。
3. 人数不足时房主添加智能体，智能体自动准备并参与完整对局。
4. 轮到玩家时，系统投出骰子并高亮合法位置；玩家移动、使用道具或结束回合，其他客户端同步显示结果。
5. 玩家到达终点，系统停止继续操作，按到达顺序和距离展示排名及对局摘要。

### 异常场景

1. 玩家输入不存在或已结束的房间码，系统不进入棋盘，提示检查房间码并允许重试。
2. 玩家提交超出移动点数、穿过障碍或重复使用道具的操作，服务端拒绝操作，保持原状态并提示原因。
3. 智能体超时、返回无法解析的内容或提出非法行动，系统记录原因并调用规则策略，在两秒内完成本回合。
4. 玩家暂时断线后重新连接，系统恢复服务端最新状态；无法恢复时回到大厅并显示明确提示。

## 4. 用户故事与验收条件

### US-01 创建并配置房间（P0）

作为房主，我希望创建房间并添加智能体，以便人数不足时也能开局。

- 给定用户输入合法昵称，当点击“创建房间”，那么系统生成可用房间码并进入大厅。
- 给定房间未满，当房主添加智能体，那么玩家列表新增一名已准备的智能体。
- 给定除房主外存在未准备真人玩家，当房主开始游戏，那么系统拒绝开始并指出未准备玩家。

### US-02 加入房间（P0）

作为受邀玩家，我希望通过房间码加入，以便和朋友进入同一局游戏。

- 给定有效且未满的房间码，当玩家提交加入请求，那么系统进入对应大厅并显示现有成员。
- 给定无效房间码，当玩家提交加入请求，那么系统停留在加入页并提示房间不存在或已结束。

### US-03 完成合法回合（P0）

作为当前玩家，我希望看见合法行动并完成移动，以便推进比赛。

- 给定轮到该玩家且移动骰结果为N，当进入移动阶段，那么界面只高亮N步内可到达的位置。
- 给定玩家选择合法位置，当确认移动，那么服务端更新坐标并广播给房间成员。
- 给定玩家选择非法位置，当提交操作，那么服务端拒绝且棋盘状态不变化。

### US-04 使用道具（P0）

作为玩家，我希望在合法时机使用道具，以便改变自己的路线或阻碍对手。

- 给定玩家持有可用道具且目标合法，当确认使用，那么系统扣除一次道具并执行效果。
- 给定信息不足或目标无效，当玩家尝试使用，那么系统说明缺少的信息并要求重新选择，不消耗道具。
- 给定道具会影响另一玩家，当用户确认目标，那么系统才执行不可撤销的本回合操作。

### US-05 智能体完成回合（P0）

作为房主，我希望智能体能在限定时间内完成合法行动，以便游戏不中断。

- 给定合法行动列表和公开局面，当轮到智能体，那么智能体在五秒内返回一个结构化行动及简短理由。
- 给定模型返回非法行动，当规则引擎校验，那么系统拒绝该建议并使用规则策略完成回合。
- 给定模型服务超时，当超过设定期限，那么系统不继续等待，记录降级原因并在两秒内选择合法行动。

### US-06 结算和复盘（P1）

作为玩家，我希望对局结束后看到排名与关键行动，以便理解胜负过程。

- 给定某名玩家到达终点，当服务端确认位置，那么对局进入已结束状态并禁止继续行动。
- 给定对局结束，当打开结算页，那么系统显示排名、回合数和智能体降级次数。

## 6. 非功能需求

- 性能：普通校园网下，合法玩家操作经服务端确认后95%的状态同步应在500毫秒内完成；智能体正常响应上限为5秒。
- 可靠性：服务端是房间状态唯一可信来源；非法操作不能改变状态；模型失败必须降级，不能阻塞对局。
- 安全：API密钥只保存在服务端环境变量中；客户端不能获得其他玩家私有信息；昵称和房间消息必须经过长度和内容校验。
- 可用性：当前阶段和可执行操作应始终可见；非法操作提示应说明原因；颜色之外再使用图标或文字区分地块。

## 7. AI能力边界

模型输入只包含智能体可见的结构化局面、角色偏好和合法行动列表；输出为一个合法行动编号、必要参数和一句理由。模型不能直接修改棋盘状态，也不能看到服务端密钥或未公开信息。允许策略不够优秀，不允许违反规则、伪造资源或无限等待。规则引擎校验所有建议，超时或失败时使用确定性评分策略。

## 8. 需求边界

本版本不处理账号社交、排行榜、付费、UGC地图、语音、复杂聊天审核、完整小游戏集合和手机原生应用。MVP的核心是从创建房间到人机对局结算的单一闭环。
