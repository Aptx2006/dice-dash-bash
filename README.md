# 当骰一棒

《当骰一棒——AI 决策 · 多人回合制桌游》是面向大学生朋友聚会和轻量线上联机的浏览器游戏。玩家加入房间后轮流投掷移动骰和工具骰，在立体方格地图中选择路线、使用道具并争夺终点；人数不足时由智能体对手根据局面自主决策补位。

本仓库已实现本地练习、基础教学与服务端管理的多人联机，可创建房间、邀请好友、添加智能体并完成竞速结算。

## 技术栈

- TypeScript、Vue 3、Vite
- Three.js
- Node.js原生HTTP服务
- 云端模型 API 与规则策略降级

联机采用原生HTTP命令与SSE状态流。默认通过Node内置SQLite持久化房间，操作提交后才响应和广播；重启可恢复未过期房间。

## 当前范围

MVP覆盖创建房间、好友加入和准备、规则校验、智能体补位、断线接管及竞速结算。关卡编辑器、账号系统、语音、商业化和复杂小游戏不在本学期范围内。

当前原型已经实现：

- 创建本地练习房间，配置1—7名策略智能体
- 创建真实6位码联机房间，2—8名真人/智能体混合，角色和颜色选择、准备、房主设置、同步重赛
- 服务端投骰、移动与道具校验，按玩家投影私有手牌，版本检查和重复提交保护
- 带身份认证的实时状态流、同标签页刷新重连、20秒断线宽限与AI接管、房主移交
- SQLite房间存档、服务重启恢复、随机序列与重复请求记录恢复、保存失败暂停与损坏数据拒绝
- Three.js立体方格棋盘、墙体与特殊地块
- 移动骰、工具骰、可达落点计算和服务端规则前的本地验证逻辑
- 工具、泥潭和加速地块
- 策略智能体寻路、风险判断、工具选择及出牌演出
- 回合推进和终点结算
- 本地自动存档：首页继续对局或查看上局结果，刷新后保留骰值、手牌、奖励与回合进度
- 基础教学、慢速动画与可调倍速、固定2.5D视角和棋盘自适应
- 桌面与窄屏响应式布局
- 大量手牌分页、按牌型筛选、固定投骰/结束入口与短横屏紧凑牌面
- 对局内战术助手：模型自主查询局面、合法行动、隔离推演与规则来源，玩家确认后执行一步移动类行动
- 可选云端智能对手：每个机器人每回合最多分析一次，模型查验行动后选择，超时或检查失败自动由本地策略接管
- 移动落点预览、危险和奖励提示、多张移动牌的独立选择，以及最近20条智能对手决策复盘

本地自动存档仅保存最近一局，使用当前浏览器的本地存储。点击“返回首页”可稍后继续，覆盖未完成存档前会询问。浏览器禁止保存时会显示警告，退出前再次提示。本地离线期间计时暂停；尚未提交的方向选择、中断的动画和未确认的助手建议不会恢复。智能对手模式、有限决策摘要与本回合云端请求占位会恢复，避免刷新后重复请求模型。联机身份另存在当前标签页会话中，刷新恢复服务端最新局面；联机不覆盖本地存档。联机默认保存到本机SQLite，当前没有账号云同步。

## 多人联机

运行`npm run dev:all`后，首页创建联机房间，在另一个浏览器页面输入6位房间号加入。所有真人连接并准备后由房主开始；人数不足可添加机器人。对局期间只能操作自己的回合，底部始终显示自己的手牌。投骰、胜负、AI与75秒计时均由服务端处理，动画倍速由各玩家独立选择。

刷新同一标签页可自动重连。断线超过20秒由AI接管，重新连接恢复真人控制；主动离开则注销身份。房主离开会移交权限，结算后房主可带全员返回大厅重新准备。无活动30分钟或创建满2小时的房间会被清理。

服务默认使用`data/rooms.sqlite`，也可在本地环境中设置`GAME_ROOM_DB`为私有位置。重启校验存档后恢复同一房间，最多等待玩家重连20秒；这段等待和停服时间不扣回合计时。数据库不可读或损坏时保留原文件并拒绝启动，运行中写入失败会回退到最后提交状态并暂停操作。数据文件被Git和开发静态服务排除，同一数据库只允许一个服务进程使用。恢复与故障测试见[房间持久化与长局交互](docs/房间持久化与长局交互.md)。

同一可信局域网的多台设备可显式启动：

```powershell
npm run dev:all -- --lan
```

启动器显示可访问的私有IPv4地址。朋友必须打开该地址下的同一服务，不能分享`127.0.0.1`。默认启动仍只在本机监听；局域网模式仅让前端监听外部地址，后端通过前端代理访问，来源限定为启动器列出的地址。不自动修改防火墙，也未部署公网。局域网跨设备实测仍需在实际网络中进行。协议、边界、课程能力映射及验收见[多人房间与权威同步](docs/多人房间与权威同步.md)。

## 规则教练

模型密钥仅在服务端配置，默认模型为`qwen3.8-flash`。设置本地环境变量`DASHSCOPE_API_KEY`，或按`.env.example`填写本地`.env`，分别启动`npm run coach`和`npm run dev`，即可在首页提问并展开规则出处。

当前知识库为`game-v3`，包含23条已确认规则和房间说明。实验5保留当时`local-v1`的20条知识快照及原始评价，不改写历史结果。运行记录、固定题集与复现方法见[实验5说明](docs/experiment5/README.md)。

## 战术助手

启动相同的AI服务后，在对局中打开“战术助手”，投骰动画结束后选择目标并分析。模型可调用4个只读工具，比较移动、冲刺、瞬步和瞬移；界面展示行动效果、风险、规则来源及分析记录。按“确认执行”才会消耗手牌。放弃、超时、取消、退出或局面变化均不会自动出牌，建议最多保留60秒。助手分析期间可以继续手动操作，计时对局的时钟也继续运行。

运行时最多8步，每次模型调用12秒、工具2秒、整次45秒，最多2次纠错。服务不可用时可继续正常游玩。该功能是一步战术建议，不保证最优路线。联机分析从服务端真实局面构造私有信息投影，确认时再次检查版本、轮次与合法行动；客户端不能借助手接口替换棋盘。实现边界和工具接口见[战术助手与运行时Harness](docs/战术助手与运行时Harness.md)。

固定合成局面的真实模型示例（不会更改浏览器存档）：

```powershell
npm run agent:demo -- --scenario=movement
npm run agent:demo -- --scenario=finish
```

加`--save`可将该次合成样例的脱敏运行轨迹保存到`docs/agent-runs/`。普通玩家请求仅在内存中保留，本服务不会自动将玩家局面或目标写入磁盘。密钥仅保存在本机环境变量或`.env`中。

## 云端智能对手

启动AI服务后创建房间，在大厅的“机器人决策”中选择“云端智能体”，添加机器人并开始对局；默认“快速策略”无需模型。云端模式只在每个机器人回合的一个有选择意义的行动局面请求模型，其余投骰、奖励、道具和阶段推进沿用规则策略。联机机器人的控制器运行在服务端，关闭某一玩家页面不会使对局停止。

模型可选择移动、冲刺、瞬步或瞬移。程序准备合法候选及检索到的规则，模型显式检查候选并根据工具结果提交一步行动；引擎复验当前局面后自动执行。后端总预算5秒，客户端保留6秒网络等待上限；无法取得有效决定时，本地策略继续本回合。动画倍速只影响演出，不改变模型预算。

对局与结算界面显示云端执行、策略接管和最近决策，可查看理由及规则编号。请求数可能包含取消或中断的尝试，因此不能把“请求数减云端成功数”直接当作降级次数。接口、课程能力映射、玩法修订与复现方法见[云端对手与玩法改进](docs/云端对手与玩法改进.md)。

固定局面评估默认只运行本地规则；显式加`--cloud`才调用真实模型：

```powershell
npm run eval:opponents
npm run eval:opponents -- --cloud --case=finish --save
```

已保存的[真实评估记录](docs/opponent-runs/evaluation.json)包含终点和安全移动样例。该评估检查单步合法性、危险规避与预期结果，不能据此宣称整局胜率更高或策略最优。

## 本地运行

需要Node.js 22.18或更新版本；本机实际使用22.23.2。该版本的内置SQLite会显示ExperimentalWarning，不影响当前测试运行。

```powershell
npm install
npm run dev:all
```

`dev:all`同时启动前端与AI服务，按Ctrl+C停止本次启动的两个服务；端口被占用时会报错，不会结束其他已有进程。若只开发界面，可单独运行`npm run dev`；未启动AI服务时仍可使用快速策略，云端功能会提示不可用或自动接管。密钥仍按上方说明配置。

生产构建：

```powershell
npm run build
```

自动测试：

```powershell
npm test
```

本地对局恢复的范围与验收记录见[本地对局恢复](docs/本地对局恢复.md)。
